# Desenho — Numeração nativa, catálogo de Produtos/Serviços e item com cálculo automático

Data: 2026-10-22 · Projeto: Site Caldemat (Vite+React+TS+Tailwind, Supabase) · Branch: `caldemat`

## Intenção e porquê

Hoje o pedido só aceita **itens de descrição livre** (descrição + quantidade + valor digitado na mão). O gerente comercial quer que **qualquer usuário credenciado** consiga passar um orçamento com **preço fixo de sistema**: os produtos/serviços têm preço definido num cadastro próprio, e o item do pedido **calcula o valor sozinho** a partir das medidas da peça. Além disso, pedido e fatura precisam de **número nativo do sistema, sequencial e inalterável**, para referência humana e rastreabilidade.

Separação de papéis que motiva o desenho: o **estoquista** cadastra Matéria-Prima (como já faz); o **gerente comercial** cadastra Produtos/Serviços e dá preço. São páginas e permissões diferentes.

## Objetivos

1. **Número nativo** do pedido (atribuído na criação) e da fatura (atribuído ao faturar), ambos sequenciais, imutáveis, exibidos com zeros à esquerda (ex.: `000123`).
2. **Nova página "Produtos/Serviços"** dentro de Cadastro, com permissão própria, onde se cadastra: nome, unidade, valor de venda, ativo, descrição.
3. **Item do pedido com dois modos:**
   - **Descrição livre** (como hoje): descrição + quantidade + valor unitário digitado.
   - **Produto/Serviço:** escolhe um produto do catálogo; unidade e preço vêm **travados** do cadastro; conforme a unidade o sistema pede medidas e **calcula o valor automaticamente**.
4. **Cálculo por unidade:**
   - **m²** → informa largura × altura → `valor = quantidade × largura × altura × valor_venda`.
   - **metro / m linear / cm / mm** → informa comprimento → `valor = quantidade × comprimento × valor_venda`.
   - **demais unidades** (Unidade(s), Dúzia(s), Quilo(s), etc.) → só quantidade → `valor = quantidade × valor_venda`.

## Não-objetivos (ficam de fora agora)

- Campos avançados de preço no cadastro: **valor de custo, preço mínimo/máximo, método de cálculo, regra min/máx**. (Decisão do usuário: cadastro **simples** agora — só unidade + valor de venda.)
- **Fatura como documento separado** com layout próprio. **Decisão (usuário delegou 2026-10-22):** a fatura é só o **número carimbado no próprio documento do pedido** — o mesmo papel passa a exibir "Pedido nº 000123" e "Fatura nº 000045". Não há impressão separada de fatura.
- Vínculo entre Produtos/Serviços e o **saldo do estoque** — continuam **independentes** (o pedido não movimenta estoque).
- Preço editável no pedido. (Decisão do usuário: **travado**.)

## Anti-objetivos (o que seria falha mesmo "funcionando")

- Dois usuários passarem **preços diferentes** para o mesmo produto. O preço é de sistema; a UI trava e **o banco é a autoridade** (trigger reaplica o preço do cadastro em item de produto).
- Número de pedido/fatura **mudar, repetir ou ter buraco controlável pelo usuário**. São nativos (sequence/identity), nunca editáveis na tela.
- Mexer no fluxo do estoquista (Matéria-Prima) ou acoplar estoque↔pedido.

## Decisões já tomadas (pelo usuário)

- Cadastro de Produto/Serviço **simples**: nome, unidade, valor de venda, ativo, descrição.
- Preço no pedido **travado** (preço de sistema).
- Numeração **com zeros à esquerda** (ex.: `000123`), para pedido e fatura.
- Medidas por unidade: **m² = largura×altura · metro/cm/mm = comprimento · resto = só quantidade**.
- Catálogo de Produtos/Serviços é uma **página nova e separada** da Matéria-Prima, com permissão própria.

## Modelo de dados (migração `0005_produtos_numeracao.sql`)

**Permissão nova** — `perfis.pode_produtos boolean not null default false`. Incluir em:
- `tem_permissao()` (novo caso `'produtos'`).
- trigger `perfis_bloqueia_escalada` (bloquear alteração por não-admin).

**Tabela nova `produtos`:**
```
id          uuid pk default gen_random_uuid()
nome        text not null
unidade     text not null         -- da lista UNIDADES (inclui "Unidade(s)")
valor_venda numeric(12,2) not null check (valor_venda >= 0)
descricao   text
ativo       boolean not null default true
```
RLS: `select` permitido a quem tem `'produtos'` **ou** `'pedidos'` (o pedido precisa listar produtos); `insert`/`update` exigem `'produtos'`.

**`pedidos` — numeração:**
```
numero        bigint generated by default as identity  -- atribuído na criação, imutável
fatura_numero bigint                                    -- atribuído ao faturar, imutável
```
- `numero`: índice único; backfill dos pedidos existentes por ordem de `data`.
- `fatura_numero`: preenchido por **sequence** `faturas_numero_seq` via trigger `pedidos_atribui_fatura` (BEFORE UPDATE): quando `status` passa a `'faturado'` e `fatura_numero` é nulo, `fatura_numero := nextval('faturas_numero_seq')`. Nunca sobrescreve.

**`pedido_itens` — item de produto + cálculo:**
```
produto_id         uuid references produtos(id)   -- nulo = item de descrição livre
unidade            text                           -- snapshot da unidade do produto
largura            numeric                        -- m²: largura | linear: comprimento
altura             numeric                        -- só m²
descricao_adicional text                          -- texto livre extra (layout "Descrição adicional")
valor_total        numeric(12,2)                  -- calculado e persistido (autoridade do banco)
```
Mantém-se: `descricao` (nome do produto em snapshot, ou o texto livre), `quantidade`, `valor_unitario` (preço por unidade em snapshot: valor do m²/metro/unidade), `obs`.

**Trigger `pedido_itens_calcula` (BEFORE INSERT OR UPDATE)** — autoridade do servidor:
- Se `produto_id` não nulo: lê o produto; **força** `valor_unitario := produto.valor_venda` e `unidade := produto.unidade` (snapshot/preço de sistema, ignora o que o cliente mandar). Calcula `valor_total`:
  - unidade `m²`: `quantidade * coalesce(largura,0) * coalesce(altura,0) * valor_unitario`
  - unidade `m`/`m linear`/`cm`/`mm`: `quantidade * coalesce(largura,0) * valor_unitario`
  - demais: `quantidade * valor_unitario`
- Se `produto_id` nulo (livre): `valor_total := quantidade * valor_unitario` (valor digitado).

**View `pedidos_total`:** trocar `sum(i.quantidade * i.valor_unitario)` por `sum(i.valor_total)`.

## Frontend

**Catálogo (novo):** `src/app/produtos/` — `ProdutosPage.tsx` + `produtos.api.ts` (listar/criar/editar/inativar). Rota `/app/cadastro/produtos`, guardada por `RequireModulo modulo="produtos"`. Card em `CadastroHome` e item no agrupador "Cadastro" do `Dashboard`, filtrados por `pode_produtos`. Formulário: nome, unidade (select de `UNIDADES`), valor de venda, ativo, descrição. Busca por nome (igual às outras listas).

**Lista de unidades:** adicionar `'Unidade(s)'` a `src/lib/unidades.ts`.

**Funcionários:** incluir a permissão **Produtos/Serviços** (checkbox) na criação/edição; backend `admin-users` passa `pode_produtos`.

**Item do pedido (`PedidoForm`):** cada item tem um seletor de modo **Produto/Serviço | Descrição livre** (padrão: Produto/Serviço).
- **Produto/Serviço:** dropdown com busca (produtos ativos) → ao escolher, preenche **Unidade** (travada) e **Valor unitário** (travado, do cadastro). Mostra **Descrição adicional**. Conforme a unidade: **m²** → Largura + Altura; **linear** → Comprimento; **demais** → nada além de Quantidade. **Valor total do item** calculado ao vivo (read-only). O payload manda `produto_id`, `quantidade`, `largura`, `altura`, `descricao_adicional` (o banco recalcula valor/total).
- **Descrição livre:** descrição + quantidade + valor unitário (como hoje).
- Medidas em **metros** (ex.: `1,000`).

**Tela/impressão do pedido (`PedidoDetalhe`):** cabeçalho mostra **Pedido nº `000123`** e, quando faturado, **Fatura nº `000045`**. Cada item mostra nome/descrição, unidade, medidas (quando houver), quantidade, valor unitário e valor total; "Descrição adicional" e "Obs" abaixo do item (padrão já adotado). Lista de pedidos mostra a coluna **Nº**.

**Helper de formatação:** `formatNumero(n, 6)` → zeros à esquerda (`000123`), em `src/lib`.

## O que fica a cargo do construtor

- TDD em todas as camadas (API, trigger/cálculo via testes de unidade do cálculo no front, componentes). Manter a suíte verde (hoje 127 testes).
- Decidir a largura de exibição dos números: **6 dígitos** (`000123`) — ajustável depois.
- Mapear unidade→modo de medida a partir de `UNIDADES` (m² = área; m/m linear/cm/mm = linear; resto = quantidade).
- Snapshot de `descricao` = nome do produto no momento (para a impressão sobreviver a rename/inativação do produto).
- Backfill do `numero` nos pedidos existentes (ordem por `data`).
- Reaproveitar `PedidoForm` (já compartilhado por novo/editar) para o novo modo de item.

## Riscos / observações

- **Editar pedido faturado** (permitido por decisão anterior) reaplica o preço atual do catálogo no item de produto — pode mudar o total de um pedido antigo se o preço mudou. Aceitável; evitar editar faturados.
- Preço travado é garantido no banco (trigger), não só na UI.
